# ADR-0001: Контракты данных и границы локального MVP

## Статус

Принято для локального MVP, 2026-11-15.

## Контекст

В репозитории есть выгрузки кейса с установками ПО, примером каталога и перечнем
названий лицензионных соглашений. Эти файлы не содержат подтверждённого реестра
закупок: нет количества купленных мест, стоимости, сроков действия, метрик
лицензирования, назначений пользователям или телеметрии concurrent-использования.

Текущий прототип должен оставаться воспроизводимым локально и не выдавать
предположения за юридические или финансовые факты.

## Решения

### 1. Источник истины и происхождение данных

- Исходные строки Excel сохраняются как факты источника.
- Для новых сведений используется `data_origin`: `excel`, `manual`, `demo`,
  `legacy`, `derived`.
- `null` означает «данные неизвестны» и не заменяется на `0`.
- Демо-права и демо-закупки будут загружаться отдельной командой и всегда будут
  помечены `data_origin=demo`.
- Обязательный seed не создаёт закупленные права, стоимости, сроки или
  назначения, которых нет в источниках.

### 2. Лицензии

Лицензионное соглашение, связь продукта с соглашением и фактически приобретённое
право — разные сущности. Поле `SoftwareProduct.license_count` сохраняется для
обратной совместимости, но не считается подтверждённой закупкой и не является
основой нового лицензионного расчёта без явного источника.

Для MVP поддерживаются метрики `device`, `user`, `concurrent`, `server`,
`subscription`, `not_applicable`, `unknown`. Нельзя складывать количества разных
метрик. При неизвестном количестве результат расчёта остаётся `null`.

### 3. Matching

Порядок принятия решения:

```text
exact normalized match → alias → deterministic fuzzy → AI suggestion → human decision
```

Точное совпадение может получить автоматический статус `matched`. Fuzzy и AI
создают рекомендацию/задачу проверки, но не изменяют каноническое сопоставление
без решения человека.

Минимальные статусы установки:

```text
matched, needs_review, unknown, confirmed, rejected
```

Решения человека сохраняются в append-only истории.

### 4. AI

Для бонусного сценария выбран Smart Matching reranker. EULA-парсинг не является
основным путём: в источниках нет текстов EULA. Natural-language assistant и
text-to-SQL отложены из-за отсутствия безопасного read-only/RLS слоя.

AI по умолчанию отключён или работает через offline mock. Любой AI-ответ должен
проходить схему, выбирать только из переданного каталога и оставаться предложением
до human approval.

### 5. Локальные ограничения

В локальном MVP не реализуются JWT, tenant/RLS, production TLS, VK Cloud
deployment, AD/LDAP, concurrent-телеметрия и полноценный Celery pipeline.
API не следует публиковать во внешнюю сеть без отдельного security review.

## Последствия

Положительные:

- расчёты не создают ложных юридических и финансовых утверждений;
- demo-сценарий можно явно отделить от фактов кейса;
- matching, лицензии и риски имеют отдельные источники истины;
- последующий переход к production-модели не требует переименовывать
  существующие факты импорта.

Отрицательные:

- на первом экране будет много `unknown`/`needs_review`;
- без реестра закупок невозможно подтвердить дефицит лицензий;
- для полноценной проверки потребуется ручной ввод прав и соглашений.
